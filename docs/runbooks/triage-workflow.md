# Triage Workflow

## 目标
将群聊中的反馈稳定转化为结构化需求池事项，并推动进入后续 PM 流程。

## 一、输入来源
- 考试群中的用户反馈
- 考官新增/修改的 issue
- 自动巡检发现的状态变化

## 二、分类规则
收到反馈后，优先判断为以下四类之一：
- `type/bug`
- `type/feature`
- `type/question`
- `type/task`

## 三、优先级规则
### P0
- 严重阻断核心流程
- 高紧急度
- 影响多人或关键场景

### P1
- 明显影响核心体验
- 需要优先推进，但不一定阻断

### P2
- 重要但不紧急
- 可进入常规排期

### P3
- 低风险优化项
- 非关键问题

## 四、归档步骤
1. 提炼一句话摘要
2. 判断类型
3. 判断优先级
4. 判断是否需要 PRD
5. 在 GitHub 创建 issue
6. 打上类型 / 优先级 / 状态标签
7. 必要时打 `needs-prd` / `needs-info`
8. 在群里同步最小必要信息

## 五、同步规则
### 需要同步时
- 新 issue 已归档
- issue 状态发生关键变化
- review 打回或通过
- issue 被标记为 `wontfix`

### 不同步时
- 仅在检查
- 无变化
- 临时中间过程
- 纯内部思考

## 六、红线
- 不得把“未复现”说成“已修复”
- 不得编造源码证据
- 不得把实现方案写进 PRD
- 不得泄露凭证或敏感信息
