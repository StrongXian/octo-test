# Cron Policy

## 目标
通过定时巡检需求池变化，形成自动闭环，而不是依赖人工触发。

## 一、扫描频率
建议每 10 分钟执行一次。

## 二、扫描对象
- 新建 issue
- issue 关闭
- label 变化
- 新评论
- review 状态变化
- `wontfix` / `approved` / `changes-requested` 等关键状态变化

## 三、输入状态
从 `state/last_scan.json` 读取：
- 上次扫描时间
- 上次已处理的事件游标
- 上次通知结果

## 四、输出要求
### 有变化
- 生成结构化变化摘要
- 写入 `logs/cron-runs/`
- 回群通知相关人和主考

### 无变化
- 仅更新本地状态
- 不向群发消息

## 五、执行记录
每次巡检至少记录：
- 执行时间
- 扫描范围
- 检测变化数量
- 变化摘要
- 是否通知
- 失败信息（如有）

## 六、限流原则
- 不高频轮询
- 遇到 GitHub 限流立即停止
- 不因追求实时性牺牲稳定性
