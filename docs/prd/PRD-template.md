# PRD: <标题>

## 1. 背景
说明需求来源、当前现状与触发原因。

## 2. 问题陈述
从用户视角描述当前问题，不写技术实现。

## 3. 目标
本次需求希望达成的结果是什么。

## 4. 非目标
明确本次不解决什么，避免范围失控。

## 5. 用户场景
### 场景 1
### 场景 2
### 场景 3

## 6. 需求说明
按用户行为和结果描述需求：
- 用户做什么
- 系统呈现什么
- 用户如何感知成功/失败/异常

## 7. 验收标准
要求写成用户可感知结果，例如：
- 用户提交操作后，3 秒内看到明确反馈
- 用户能区分成功、失败、权限不足三种状态
- 关键流程中不会出现含糊或无反馈状态
- 提示文案对非技术用户可理解

## 8. 风险与待确认项
列出当前仍待确认的问题或边界。

## 9. 附注
如有必要，补充 issue 链接、来源说明等。
