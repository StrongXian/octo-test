# Design Highlights

## 亮点一：双 Agent 分工
一个 Agent 负责源码问答与需求归档，一个 Agent 负责 PRD 与 review，减少上下文混杂，更接近真实产品协作。

## 亮点二：证据优先
关于 `octo-server` 的结论必须尽量给出源码路径和行号；证据不足时明确说“不确定”，不做猜测。

## 亮点三：静默巡检
定时任务只在需求池有变化时才通知群聊，无变化时不发消息，避免无效噪音。

## 亮点四：PRD 只写 What
PRD 严格只描述用户问题、目标、场景和验收标准，不混入技术实现细节。

## 亮点五：可核验闭环
从 issue、PRD、review 到巡检记录，都有可见产物，便于考试当天核验。
